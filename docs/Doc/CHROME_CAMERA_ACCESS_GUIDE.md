# 🎥 Chrome Camera Access - Local Development Guide

## Problem
Chrome blocks `getUserMedia()` (camera/microphone access) on **non-HTTPS** sites, except for:
- `http://localhost` or `http://127.0.0.1`
- Sites served over HTTPS

When accessing Flask via LAN IP (e.g., `http://192.168.8.10:5000`), Chrome blocks camera access.

---

## ✅ Solution Options (Fastest → Most Secure)

### **Option A: Use localhost (Fastest - No Setup)**

**When to use:** Testing on same machine as Flask server

**How it works:** Chrome treats `localhost` as secure context

**Steps:**
1. Ensure Flask binds to `0.0.0.0` or `127.0.0.1` (check `run.py`)
2. Access via: `http://localhost:5000` (instead of `http://192.168.8.10:5000`)

**Pros:**
- ✅ Zero setup
- ✅ Instant
- ✅ No certificates needed

**Cons:**
- ❌ Can't test from other devices (phone, another PC)
- ❌ Can't test IP Camera integration properly

**Verdict:** Use this for quick webcam testing on dev machine only.

---

### **Option B: Chrome Flag (Fast - Temporary)**

**When to use:** Quick testing with LAN IP, temporary solution

**PowerShell Command:**
```powershell
# 1. Close ALL Chrome windows first (important!)

# 2. Run Chrome with flag (replace IP:port with yours)
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --user-data-dir="C:\ChromeDevSession" `
  --unsafely-treat-insecure-origin-as-secure="http://192.168.8.10:5000" `
  "http://192.168.8.10:5000/presensi_face"
```

**What this does:**
- Creates a separate Chrome profile (`ChromeDevSession`)
- Treats your local IP as "secure" for camera access
- Opens the page directly

**Pros:**
- ✅ Fast (30 seconds)
- ✅ Works with LAN IP
- ✅ Can test from dev machine
- ✅ No certificate needed

**Cons:**
- ❌ Must close all Chrome windows first
- ❌ Separate profile (different bookmarks/history)
- ❌ Security flag reduces protection
- ❌ Doesn't work from other devices (they need flag too)

**Cleanup:**
Just close the Chrome window. To remove the profile folder:
```powershell
Remove-Item -Recurse -Force "C:\ChromeDevSession"
```

**Verdict:** Good for quick dev testing on your PC.

---

### **Option C: HTTPS with mkcert (Recommended - Secure)**

**When to use:** Professional dev setup, testing from multiple devices

**Installation (One-time):**

#### 1. Install mkcert

**Via Chocolatey:**
```powershell
choco install mkcert -y
```

**Via Scoop:**
```powershell
scoop install mkcert
```

**Via winget:**
```powershell
winget install mkcert
```

**Manual (if above fail):**
1. Download from: https://github.com/FiloSottile/mkcert/releases
2. Extract `mkcert-v*.exe` to `C:\Windows\System32\` (rename to `mkcert.exe`)

#### 2. Install Local CA (Certificate Authority)
```powershell
mkcert -install
```
Output: `Created a new local CA... The local CA is now installed in the system trust store!`

#### 3. Generate Certificate
```powershell
# Navigate to project
cd C:\Users\Admin\Desktop\Project\FINAL_DEAD\DEAD

# Generate cert for localhost + your LAN IP
mkcert localhost 127.0.0.1 ::1 192.168.8.10

# This creates:
# - localhost+3.pem         (certificate)
# - localhost+3-key.pem     (private key)
```

#### 4. Create SSL Runner Script

Create `run_ssl.py` in project root:

```python
from run import app

if __name__ == '__main__':
    # Use the certificate files generated by mkcert
    ssl_context = (
        'localhost+3.pem',          # certificate
        'localhost+3-key.pem'       # private key
    )
    
    app.run(
        host='0.0.0.0',             # Bind to all interfaces
        port=5000,
        ssl_context=ssl_context,
        debug=True
    )
```

#### 5. Run Flask with HTTPS
```powershell
python run_ssl.py
```

#### 6. Access via HTTPS
```
https://localhost:5000/presensi_face
https://192.168.8.10:5000/presensi_face
```

**Pros:**
- ✅ Trusted certificate (no warnings)
- ✅ Works on all devices on same network
- ✅ Realistic production-like setup
- ✅ Professional approach
- ✅ Camera access works everywhere

**Cons:**
- ⚠️ 10-15 minutes initial setup
- ⚠️ Requires mkcert installation
- ⚠️ Slightly more complex

**Verdict:** Best for serious development, especially if testing IP Camera with multiple devices.

### **Option D: ngrok Tunnel (External Access)**

**When to use:** Testing from external network, demo to client, mobile testing

**Installation:**
1. Download: https://ngrok.com/download
2. Extract `ngrok.exe` to `C:\ngrok\`
3. (Optional) Sign up and add auth token

**Usage:**
```powershell
# Terminal 1: Start Flask (normal HTTP)
cd C:\Users\Admin\Desktop\Project\FINAL_DEAD\DEAD
python run.py

# Terminal 2: Start ngrok tunnel
cd C:\ngrok
.\ngrok http 5000 --host-header=localhost
```

**Output:**
```
Forwarding  https://abc123.ngrok.io -> http://localhost:5000
```

**Access:**
```
https://abc123.ngrok.io/presensi_face
```

**Pros:**
- ✅ HTTPS automatically provided
- ✅ Works from anywhere (public URL)
- ✅ No certificate setup
- ✅ Great for mobile testing
- ✅ Can share with clients

**Cons:**
- ❌ External tunnel (less private)
- ❌ Temporary URL (changes each run)
- ❌ Requires internet
- ❌ Free tier has rate limits

**Verdict:** Use for external testing or demos, not daily dev work.

## 🔧 Troubleshooting

### Chrome still blocks camera

**Check:**
1. Are you using HTTPS? (Look for padlock 🔒 in address bar)
2. Did you allow camera permission when Chrome asked?
3. Is another app using the camera?

**Fix:**
```
Chrome Settings → Privacy and security → Site Settings → Camera
→ Find your site → Change to "Allow"
```

### Certificate error in Chrome

**Symptom:** "Your connection is not private" (NET::ERR_CERT_AUTHORITY_INVALID)

**Fix for mkcert:**
```powershell
# Reinstall CA
mkcert -uninstall
mkcert -install

# Restart browser
```

### Flask won't start with SSL

**Error:** `[SSL: CERTIFICATE_VERIFY_FAILED]`

**Fix:**
- Check certificate filenames match in `run_ssl.py`
- Ensure certificate files are in same folder as `run_ssl.py`
- Use absolute paths if needed:
  ```python
  ssl_context = (
      'C:/path/to/cert.pem',
      'C:/path/to/key.pem'
  )
  ```

### mkcert command not found

**Fix:**
```powershell
# Add to PATH (if installed manually)
$env:Path += ";C:\path\to\mkcert\folder"

# OR use full path
C:\path\to\mkcert.exe -install
```

## ⚠️ Security Notes

### DO NOT:
- ❌ Use `--disable-web-security` flag (disables all security)
- ❌ Ignore HTTPS certificate warnings in production
- ❌ Share your private key (`*-key.pem` files)
- ❌ Commit certificates to Git

### DO:
- ✅ Use mkcert for local HTTPS (best practice)
- ✅ Keep certificates out of version control (`.gitignore`)
- ✅ Use proper SSL in production (Let's Encrypt, etc.)
- ✅ Test in production-like conditions

## 📱 Testing from Mobile/Other Devices

### With mkcert HTTPS:

1. **Find your PC's LAN IP:**
   ```powershell
   ipconfig | findstr IPv4
   ```
   Example output: `192.168.8.15`

2. **Access from mobile on same WiFi:**
   ```
   https://192.168.8.15:5000/presensi_face
   ```

3. **If certificate warning appears:**
   - iOS/Android: May show warning first time
   - Click "Advanced" → "Proceed" (safe for local dev)
   - OR: Install mkcert CA on mobile device:
     - Export CA: `mkcert -CAROOT` (shows folder)
     - Copy `rootCA.pem` to phone
     - Install as trusted certificate

### With ngrok:

1. Start ngrok (see Option D above)
2. Use the `https://abc123.ngrok.io` URL on any device
3. No certificate warnings (ngrok provides valid cert)

## 🎓 Best Practices

### For Development:
1. Start with **localhost** for quick webcam tests

1. Must use **LAN IP** (not localhost) to access camera

3. Test HTTPS works before testing camera

1. Document SSL setup in README
2. Share mkcert installation script
3. Each developer generates own certificates
4. Never commit certificates to repo

## ❓ Need Help?

If issues persist:
1. Check Chrome DevTools Console (F12) for error messages
2. Verify Flask is running on correct port
3. Test with simple `getUserMedia()` test page first
4. Ensure camera works in other apps (Windows Camera app)

**Common Errors:**
- `NotAllowedError`: User denied permission or site not trusted
- `NotFoundError`: No camera detected
- `NotReadableError`: Camera in use by another app
- `SecurityError`: Site not secure (use HTTPS)
